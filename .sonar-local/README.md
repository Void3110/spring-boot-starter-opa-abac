# Local SonarQube — the repo's static-analysis quality gate

Run a pinned SonarQube rule set against your working tree **before committing/pushing**. This
public project has no hosted SonarQube, so this local stack **is** the Sonar gate: the
`/deep-review` validate phase and the autonomous per-ticket ★review both expect a
`CLEAN — 0 open findings` on the changed files.

## What it pins

The stack pins **`sonarqube:26.3.0.120487-community`** and seeds an **`OPA-ABAC Local Java`**
profile — an owned copy of that analyzer's built-in **`Sonar way`** Java rules. Owning the copy
(instead of using the built-in directly) means local strictness can be tightened later without
forking away from a reproducible baseline. The quality gate is findings-only for now
(`new_bugs` / `new_vulnerabilities` / `new_code_smells` all 0); a coverage floor is a possible
later tightening.

The pin exists **only for reproducibility** — this project answers to no external Sonar server, so
the version and profile are free to advance (newer community builds exist; a bump re-baselines the
findings). The upgrade evaluation + baseline triage are tracked in
`docs/to-do/planning/QUALITY-GATE-SONAR-BASELINE/`.

## One-time setup

```bash
docker compose -f .sonar-local/docker-compose.yml up -d   # boots SonarQube + Postgres (~1-2 min)
./.sonar-local/bootstrap.sh                                # seeds profile + gate + project, mints a token
```

`bootstrap.sh` is idempotent. It sets the admin password (default `OpaAbacLocal!2026x` — 26.x
enforces a complexity policy), copies the built-in profile, creates the gate, and writes an
analysis token to `.sonar-local/token` (gitignored). Web UI: <http://localhost:19244>
(`admin` / `OpaAbacLocal!2026x`).

## Scan the working tree

```bash
./.sonar-local/sonar-local.sh                 # DEFAULT: findings on files changed vs origin/main
./.sonar-local/sonar-local.sh --all           # full-tree audit (every open finding)
./.sonar-local/sonar-local.sh --rules S112,S1192   # only these rules
./.sonar-local/sonar-local.sh --no-scan       # re-query the last scan without re-running gradle
```

The scan runs `./gradlew testClasses sonar` itself (Sonar reads bytecode; no test execution).
**Default scope is CHANGED files** (the pre-push signal: "did *my* change add a smell?").
`--all` is for an occasional baseline audit — it shows the full tree, including any standing
by-design false-positives (recorded in the Mulch **`quality-gate-sonar`** domain —
`ml prime quality-gate-sonar` before judging a finding; do not re-fix a documented FP).

## Stop / reset

```bash
docker compose -f .sonar-local/docker-compose.yml down       # stop, KEEP data
docker compose -f .sonar-local/docker-compose.yml down -v    # wipe data (re-bootstrap needed)
```

## Sharing one instance across repos

SonarQube is memory-hungry (~2 GB+ per instance) and Docker Desktop VMs are often capped, so
avoid running several local SonarQube stacks at once. Everything the bootstrap creates is
**project-scoped** (the profile and gate are bound to `spring-boot-starter-opa-abac-local`,
never set as instance defaults), so the scripts can target any already-running compatible
26.3.0 instance instead of booting this one:

```bash
SONAR_LOCAL_URL=http://localhost:<port> SONAR_LOCAL_ADMIN_PW=<its admin pw> ./.sonar-local/bootstrap.sh
SONAR_LOCAL_URL=http://localhost:<port> ./.sonar-local/sonar-local.sh
```

## Files

| File | What |
|------|------|
| `docker-compose.yml` | SonarQube 26.3.0-community + Postgres 16, port **19244** |
| `bootstrap.sh` | Seed profile + gate + project + token (idempotent, project-scoped) |
| `sonar-local.sh` | Scan the working tree → print findings (changed-files by default) |
| `token` | Local analysis token — **gitignored**, regenerated by bootstrap |

## Tightening the rules (later)

`OPA-ABAC Local Java` is a non-built-in profile you **own**. Activate extra rules in the Sonar
UI (Quality Profiles → OPA-ABAC Local Java), then export
(`api/qualityprofiles/backup?language=java&qualityProfile=OPA-ABAC%20Local%20Java`) and commit
the XML here to version-control the divergence. Until it diverges, the pinned image's built-in
`Sonar way` is the reproducible baseline and no XML needs committing.
