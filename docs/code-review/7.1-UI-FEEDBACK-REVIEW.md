## Fail-closed verification

The fail-closed/authz lens confirmed every error/empty path lands on deny/empty: the exemption
activates only on `data.config.root_read_tag_exemption == true` (absent/false → strict, pinned by
E5/E6); the list residual folds the tag conjunct out only under the concrete-true flag (verified
`opa eval --partial` in both states); `TagAssignmentService`/`TagDefinitionClient` still reject (not
widen) on dictionary outage; the SPA's `likelyDenied` predictions only mark, never gate.

## Security audit

The removed `@OpaPreAuthorize` on `listTeamTagDefinitions` GET was examined for disclosure: it
returns byte-identical rows to the bearer-only flat listing (same service method), so no new
disclosure class; mutations keep `team:define-tags` (pinned by G2/G3 + the new G3b read-200 cell).
Product-list cache seeding writes to the **request-scoped** `AbacResourceCache` — no cross-request
or cross-subject reuse. No injection surfaces, no secrets in logs/errors, no authn edge defaulting
to a subject.

## Concurrency & idempotency

row + unchanged `@Version` on deny); the gate-window race cell (I4) was **deliberately migrated** to
the product PUT — the last statically-annotated mutation, the same migration Phase 6.5 made for
categories — and the persistence lens confirmed the remaining coverage is sound (version binding in
the mutating tx, drift → 409, unchanged).
