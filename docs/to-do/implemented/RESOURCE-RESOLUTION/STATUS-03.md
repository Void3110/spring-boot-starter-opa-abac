## Architecture review + refactor

Review path: conditional-evaluation ordering, classpath-safety, advice-ambiguity analysis, additivity
of the existing nested configs.

- **No declaration-order hazard:** the support bean consumes `AncestorResolver` via `ObjectProvider`
  (instantiation-time), and `@ConditionalOnBean` references only a user-defined bean — both safe per
  Spring's condition-evaluation rules. The nested class is still declared after
  `HierarchyAutoConfiguration` for reading order.
- **Classpath safety:** the nested class file (not the outer) carries the security-type references;
  with security filtered the condition short-circuits via ASM metadata — the existing
  security-absent test (U33) stays green. The dao advice mirrors this for `org.springframework.dao`.
- **Advice ambiguity:** extending `AbstractProblemAdvice` would have duplicated the
  `AccessDeniedException` handler against every service's own advice (cross-advice handler resolution
  is order-dependent) — standalone with its own `ProblemDetailFactory` produces the same body shape
  with zero ambiguity. Recorded in Mulch.
- **Deviation (named):** `ResourceResolutionSupport` accessors went package-private → **public**
  (T2 type, visibility-only change in this commit) — required for the U15 delegation assertion from
  the `autoconfigure` test package, and correct for a composition carrier consumed across packages.
- Existing nested configs and bean methods byte-identical except the manager bean's additive
  `ObjectProvider` parameter.

## Decisions

- The dao advice is **standalone**, not an `AbstractProblemAdvice` subclass (see review note).
- The support bean binds the chain supplier inline (`hierarchyResolver::ancestorsOf`) rather than
  registering a separate `AncestorChainSupplier` bean — one less public bean, same override path
  (override `ResourceResolutionSupport` itself).
