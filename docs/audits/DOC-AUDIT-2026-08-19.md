#### [Critical/CLAIM_FALSE] `docs/architecture/TWO-LAYER-AUTHORIZATION.md` — line 43-44 ("Layer 2 — app: fine-grained") and line 79-81 ("Per-type policy documents"): "asks OPA whether the **action** is permitted on the **resource type** — `input.role_definition.permissions[input.resource.type]`" / "a rule allows when the action verb is present in `input.role_definition.permissions[input.resource.type]`"

- **Reality now:** Since Phase 6.5 / ADR 0007 `role_definition.permissions[<type>]` holds COARSE category tokens (READ/WRITE/TAG/GRANT), not verbs. `infra/opa/policies/catalog.rego:57-61` is `allow if { verb in permissions.effective_actions(input.role_definition, input.resource.type); tags_satisfied; not denied }` — the tokens are expanded through `data.permission_categories` and then narrowed by `denied_actions` in `infra/opa/policies/permissions.rego` (`tokens_for` at :33, `denied_for` at :46, wildcard `"*"` fallback included). `infra/opa/policies/category.rego` and `product.rego` use the same `permissions.effective_actions` shape.
